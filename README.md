# Static Savvy Media

Premium futuristic digital marketing agency website. Frontend-only static website built with **React + JavaScript + JSX + CSS + React Router + Vite**.

## Stack

- React 19
- React Router 7
- Vite 8
- Plain CSS (design tokens + component styles)

## Getting Started

```bash
npm install
npm run dev
```

## Build

```bash
npm run build
npm run preview
```

## Contact form API

The contact form (`src/components/sections/ContactFormSection.jsx`) posts JSON to
`/api/submit-contact`, a Vercel Function (`api/submit-contact.js`, Node.js runtime). The logic
(honeypot, reCAPTCHA v2 check, validation, SMTP email via nodemailer) lives in
`server/contact/submit-contact.js` and is shared by:

- `api/submit-contact.js`: production and preview deployments on Vercel
- `vite.config.js`: `npm run dev` serves the same endpoint through a dev middleware
- `netlify/functions/submit-contact.js`: `npm run dev:netlify` only (legacy, not used in production)

On a successful submission the form pushes `{ event: 'generate_lead' }` to the GTM `dataLayer`.
GTM needs a GA4 Event tag (event name `generate_lead`) fired by a Custom Event trigger on
`generate_lead` for it to reach GA4.

`npm run test:contact` runs the function against a local fake SMTP server (no email is sent).

## Environment Variables

Copy `.env.example` to `.env` and fill in real values:

- SMTP\_\* / MAIL\_FROM\* / ADMIN\_EMAIL — outgoing mail for the contact form.
- `VITE_RECAPTCHA_SITE_KEY` / `RECAPTCHA_SECRET_KEY` — Google reCAPTCHA v2
  keys ([get them here](https://www.google.com/recaptcha/admin)). The
  reCAPTCHA widget only renders once `VITE_RECAPTCHA_SITE_KEY` is set; the
  form works without it in the meantime.
- `VITE_GTM_ID` / `VITE_CLARITY_ID` — already wired directly into
  `index.html` (Google Tag Manager + Microsoft Clarity), listed here for
  reference only.

On Vercel, set the server-side variables (SMTP\_\*, MAIL\_FROM, MAIL\_FROM\_NAME, ADMIN\_EMAIL,
RECAPTCHA\_SECRET\_KEY) and `VITE_RECAPTCHA_SITE_KEY` under **Project → Settings → Environment
Variables** for Production (and Preview if you test forms on previews). `VITE_` variables are
baked in at build time, so redeploy after changing them.

## Hosting, routing & SEO files

Production (`www.staticsavvymedia.com`) is served by **Vercel** from the `main` branch. The bare
domain redirects to www at the domain level. `netlify.toml`, `public/_redirects` and
`netlify/functions` are only used by `netlify dev` locally; Vercel ignores them.

The app is a client-side SPA, so the server has to know which URLs are real pages:

- `vercel.json` is **generated** by `npm run seo:generate`. It contains:
  - one rewrite to `/index.html` per real route, plus `/blog/:slug/` for Sanity posts
    (unknown URLs get a real 404, served with `public/404.html`)
  - `/path` → `/path/` (308) for real routes. The trailing-slash form is canonical.
  - 301s for duplicate routes (pricing aliases, `/blog/seo`, `/blog/geo-aeo`) and for old
    Wix/WordPress URLs listed in `scripts/seo/legacy-redirects.csv`
- `public/sitemap.xml` and `public/robots.txt` are generated by the same script (www host,
  trailing slashes, Sanity posts with `lastmod`).
- **After adding or removing a non-blog route in `src/routes/AppRoutes.jsx`, run
  `npm run seo:generate` and commit the result.** `npm run seo:check` fails if `vercel.json` is
  out of date. Otherwise the new page will return 404 on direct load.
- Canonical URLs: `SITE_URL` in `src/utils/constants.js` (default `https://www.staticsavvymedia.com`,
  overridable with `VITE_SITE_URL`). `setSeo()` normalises every canonical/og:url to
  `https://www.staticsavvymedia.com/<path>/`.
- After a deploy, run `scripts/test-after-deploy.sh` (or `BASE=<preview url> scripts/test-after-deploy.sh`).

## Project Structure

```
StaticSavvyMedia/
├── public/                 # Static public assets (favicon, robots, sitemap, images)
├── src/
│   ├── assets/             # Images, icons, fonts imported by components
│   ├── components/         # Reusable components (common, navigation, hero, cards, sections, animations)
│   ├── layouts/            # MainLayout, LandingLayout, ContentLayout, BlogLayout
│   ├── pages/              # Route-level page components (one per URL)
│   ├── templates/          # 12 reusable page templates (T01–T12)
│   ├── data/               # Data-driven configuration (services, locations, industries, ...)
│   ├── routes/             # AppRoutes.jsx — all React Router routes
│   ├── styles/             # CSS architecture (tokens, global, typography, components, pages, templates)
│   └── utils/              # constants, helpers, seo, schema
├── index.html
├── package.json
└── vite.config.js
```

## Architecture

```
Page → Template → Reusable Sections → Reusable Components → Data
```

- Every URL has one page component in `src/pages/`.
- Pages consume one of the 12 reusable templates in `src/templates/`.
- Templates compose reusable sections and components.
- `src/data/*.js` files are structural placeholders and will be populated in a later phase.
- No backend, no database, no CMS. Pure static frontend.

## Design Direction

Dark mode, neon gradient, glassmorphism, premium digital agency UI. Design tokens live in `src/styles/variables.css`.
